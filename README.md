# 讲座票管理系统

本项目是一个本地运行的轻量 Web 管理系统，使用 Python 标准库、SQLite 和原生前端实现，不需要安装第三方依赖。

## 启动

```powershell
python server.py --host 127.0.0.1 --port 8000
```

浏览器打开：

```text
http://127.0.0.1:8000
```

管理员端：

```text
http://127.0.0.1:8000
```

后台登录密码默认是：

```text
admin123456
```

正式部署时请设置环境变量 `ADMIN_PASSWORD`，例如：

```powershell
$env:ADMIN_PASSWORD = "换成一个强密码"
python server.py --host 0.0.0.0 --port 8000
```

学生只读查询端：

```text
http://127.0.0.1:8000/student
```

数据会保存在 `data/tickets.db`。

## 功能

- 一键导入学生名单：识别 `学号`、`姓名/学生姓名`、`学历层次` 等字段。
- 一键导入讲座活动：表格需包含 `姓名`、`学号`、`活动名称`、`活动时间`；只有姓名和学号同时匹配才会加 1 张票。
- 导入失败提示：会返回失败行号、学号、姓名和原因。
- 导出汇总：导出 `学号`、`学历层次`、`讲座票数量`、`现有讲座票数量（变量）/讲座票要求`，不包含姓名。
- 管理员可在页面中手动修正学生学历层次和现有讲座票数量。
- 学生可在只读查询端使用学号查看自己的讲座票进度和已记录讲座。
- 学生可针对后台已录入过的讲座活动提交反馈，管理员端可查看反馈记录。
- 管理员可处理反馈状态，填写处理备注，并对确认属实的反馈一键补票。
- 后台导入、手动改票、处理反馈和补票前会自动备份数据库到 `data/backups/`，默认保留最近 50 份。

## 部署建议

可以在正式部署时配置两个完全不同的网址：

- 后台端：`admin.example.com`
- 学生端：`ticket.example.com`

如果使用 Nginx、Apache、宝塔、学校服务器网关等反向代理，可以把两个域名都转发到同一个 Python 服务，再分别指向 `/` 和 `/student`。即使使用同一个服务，后台端也已经有密码登录保护。

## Render 免费部署

项目已包含 `render.yaml`，可以在 Render 里用 Blueprint 或 Web Service 直接部署。

基本配置：

- Runtime：Python
- Build Command：`python -m py_compile server.py`
- Start Command：`python server.py`
- Environment Variable：设置 `ADMIN_PASSWORD` 为后台强密码

Render 会自动提供 `PORT` 环境变量，程序也会在 Render 环境下默认监听 `0.0.0.0`。

注意：Render 免费 Web Service 的本地文件系统不是持久化存储。本项目免费部署时适合试运行和演示，上传的 SQLite 数据库、反馈和自动备份可能在服务重启、休眠或重新部署后丢失。正式使用建议改用 PostgreSQL，或使用带持久磁盘的部署方案。

## Excel 模板

系统页面右上角提供：

- 学生名单导入模板
- 讲座活动导入模板

也可以直接导入教务系统导出的宽表，系统会优先识别 `学号`、`学生姓名`，并尝试从培养层次、学生类别、学位类型等字段推断学历层次。
